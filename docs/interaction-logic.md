# AI Arena Duel - 交互逻辑设计文档

本文档总结了 **AI Arena Duel** 对战大厅页面的核心交互逻辑、校验规则及视觉反馈机制，旨在为前端开发和产品演示提供清晰的逻辑指引。

---

## 1. 核心交互原则：互斥选择 (Mutual Exclusivity)

系统采用“卡片选择”与“自定义输入”二选一的逻辑。用户必须为每个维度的参数（角色、装备）提供输入，但不能同时使用预设卡片和自定义 Prompt。

### 1.1 角色选择互斥 (Character Selection)
- **卡片 -> 输入框**：当用户点击并选中一张“预设角色卡片”时：
    - 该玩家区域下的“Custom Character”模式输入框变为灰色（Disabled）。
    - 输入框背景透明度降低，鼠标指针变为禁止点击状态。
    - 文本区域不可编辑。
- **输入框 -> 卡片**：当用户在“Custom Character”输入框中开始填写文字或上传参考图时：
    - 预设角色卡片区域变为灰色（Disabled）。
    - 任何已选中的卡片将自动取消选中状态。
    - 卡片列表区域覆盖半透明层。

### 1.2 装备选择互斥 (Weapon Selection)
- **卡片 -> 输入框**：当用户点击并选中一张“预设装备卡片”时：
    - 该玩家区域下的“Custom Weapon”模式输入框变为灰色（Disabled）。
    - 文本区域锁定。
- **输入框 -> 卡片**：当用户在“Custom Weapon”输入框中填写文字或上传参考图时：
    - 预设装备卡片区域变为不可选状态，已选项清除。

---

## 2. 自定义输入区 Tab 切换逻辑 (Custom Prompt Tabs)

自定义输入区域通过 Tab 按钮在“角色”与“装备”两个模式间切换：
- **状态保留**：切换 Tab 时，之前在另一个模式下输入的文本或上传的图片必须完整保留，不会清除。
- **独立控制**：
    - 若用户仅在“角色”维度选择了卡片，则切换到“Custom Character”Tab 时输入框变灰，但切换到“Custom Weapon”Tab 时输入框仍可输入。
    - 若用户在“角色”和“装备”维度都选择了卡片，则“Custom Character”和“Custom Weapon”两个 Tab 下的输入框均会变灰。

---

## 3. 战斗开始校验逻辑 (Start Battle Validation)

用户点击中央底部的 **"START BATTLE"** 按钮时，系统执行以下强校验：

### 3.1 必备参数校验
系统检查两个玩家的四个必要参数是否已提供：
1. **Player A - Character** (卡片 或 Prompt)
2. **Player A - Weapon** (卡片 或 Prompt)
3. **Player B - Character** (卡片 或 Prompt)
4. **Player B - Weapon** (卡片 或 Prompt)

### 3.2 校验反馈
- **通过校验**：进入“生成中”状态（弹出生成等待弹窗，20秒倒计时）。
- **校验失败**：若缺少任何一个参数，系统会弹出**高亮警告弹窗**（Warning Modal），提示用户具体哪个玩家的哪个参数尚未配置，阻止进入生成流程。

---

## 4. 中央擂台区域状态演变 (Central Arena States)

中央 16:9 区域根据用户操作流程动态更新内容：
1. **默认状态 (Waiting)**：循环播放“等候用户加入”的默认背景视频。
2. **生成状态 (Generating)**：显示生成进度提示及对峙图加载状态。
3. **播放状态 (Battle Video)**：展示最终生成的完整 AIGC 格斗视频。
4. **结束状态 (Result)**：视频结束后弹出胜负结果弹窗，提供“继续守擂”或“退出游戏”选项。

---

## 5. 视觉反馈规范 (UI Feedback)

- **选中态**：
    - Player A 选中：红色霓虹边框 + 红色发光阴影。
    - Player B 选中：蓝色霓虹边框 + 蓝色发光阴影。
- **不可选态 (Disabled)**：
    - `opacity: 0.4`
    - `cursor: not-allowed`
    - `pointer-events: none`
- **悬停态 (Hover)**：卡片轻微上浮（Scale 1.05）并增加边框亮度。
